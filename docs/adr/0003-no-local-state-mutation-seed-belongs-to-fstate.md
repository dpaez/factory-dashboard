# 3. The dashboard never mutates or enriches factory state; seeding belongs to fstate

Date: 2026-10-02

## Status

Amended by ADR 0004 (2026-10). The read-only posture is now enforced by the connection itself (`node:sqlite` `readOnly: true`) — stronger than the convention this ADR asked for. The "including scratch copies" clause is reversed: tests build and populate scratch v2 databases from the vendored reference schema (`test/fixtures/state-schema.sql`), and the schema's own `CHECK` constraints and triggers are what keep fixtures from describing impossible states. `fstate seed` does not exist and is no longer awaited.

## Context

Issue #2 asked for a way to populate a scratch factory DB with authentic multi-ticket state for demos,
design work, and tests. The first implementation drove real `fstate` CLI mutations (fine) but then added
a local "enrichment" step that reopened the scratch SQLite DB and rewrote timestamps and context columns
the CLI cannot write, to give rows realistic ages. Five review rounds followed. Every round found seeded
rows in states the CLI cannot produce (updated-before-created, review-after-last-update, events newer
than the columns they wrote, five tickets sharing one timestamp), because the CLI's causal rules — one
mutation, one clock, several columns written together — must be re-derived at every write site by
anything that patches state after the fact. The reviewer caught each variant; the worker's local tests
never did, and twice pinned an impossible ordering as an invariant.

## Decision

The dashboard repository does not write, enrich, or backdate factory state at all — including scratch
copies. Test/demo data population is an upstream `fstate seed` command (requirement filed on
factory-skills with the causal-invariant contract as acceptance criteria). Inside the CLI, a seed
command can stamp ages *within* its own mutations, where the causal rules hold by construction.
Dashboard tests that need rows use inline fixtures for pure modules; browser-level fixtures wait for
upstream or are generated by consuming `fstate seed` output read-only.

## Consequences

- FD-2's local harness work was discarded unmerged (branch deleted at base; issue #2 labeled wontfix).
- The dashboard's read-only posture (PRODUCT.md, ADR 0001) now covers writes too: zero write paths to
  factory state exist or may be added in this repo.
- Demo realism (aged tickets, context pressure near limits) is unavailable until upstream ships `seed`;
  UI work that needs it either waits or uses flat-age data and says so.
- The causal-invariant contract (parent >= child timestamps; events.at equals the row timestamps its op
  wrote; review_updated_at <= updated_at; message_at <= updated_at; complete tickets newer than their
  tasks) travels upstream as acceptance criteria instead of living as tribal knowledge here.
